# Продуктовое описание (критерий JMLC)

## Проблема

Аналитики девелопера оценивают **тысячи земельных участков** в Москве: стройка, деградация, недоиспользование. Спутник не видит дворы и фасады; текст в GPKG часто **не различает класс** (1712 участков с одной фразой «зелень во дворах»).

## Целевая аудитория

- Урбанисты и аналитики застройщика
- Команды, работающие с GPKG и кадастром
- Пилот: ПИК AI Lab

## Конкуренты / альтернативы

| Подход | Минус |
|--------|-------|
| Ручной просмотр панорам | Медленно, не масштабируется |
| Только текст GPKG | 87.6% на полном GPKG, но ошибается на «зелень» vs жилой фонд |
| Спутниковая CV | Не видит уличную перспективу |
| **Наше решение** | Панорама + ML + UI для правок |

## MVP

1. Загрузка GPKG
2. Автоклассификация по панораме (6 UTT)
3. Карта Leaflet + статус панорамы
4. Правка класса аналитиком
5. Экспорт GPKG

Реализация: `web_app/` (Flask + Leaflet).

## Импакт

- Сокращение времени первичного скрининга участков
- Единая таксономия UTT для аналитиков
- Обратная связь: **7535 участков** с правками в GPKG → дообучение

## Обратная связь

- GPKG с правками аналитиков — gold labels для дообучения
- Сравнение ML ↔ аналитик и потолок домена: `docs/METRICS.md`

## Метрики продукта
