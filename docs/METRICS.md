# Метрики и валидация

Документ для жюри JMLC: **что измерено, на каких данных, с какими ограничениями**.
Все цифры — из реальных прогонов проекта (`results/*.json`), без округлений «в свою
пользу».

## Как считаем

- **Сплит по `object_id`**, а не по кропам — кропы одного участка (разные сезоны и
  азимуты) не попадают одновременно в train и val. Пересечение объектов train/val = 0.
- Отдельно две принципиально разные валидации:
  - **research val** — отложенная выборка нашего датасета (content-метки);
  - **GPKG аналитиков** — продуктовая проверка на реальных правках (другой домен).
- Метрики: accuracy, macro-F1, **balanced macro-F1** (macro-F1 на подвыборке с cap
  35 объектов на класс — убирает перекос доминирующего `active_urban`).

## Эволюция подхода (ранний пайплайн, OSM-метки)

Сначала обучали end-to-end на сырых OSM-метках. Ключевой скачок дала чистка азимутов
(см. ниже), а не смена архитектуры.

| Модель | Accuracy (грязный val) | Accuracy (чистый val) |
|--------|------------------------|-----------------------|
| OpenCLIP zero-shot | 0.14 | 0.20 |
| ResNet18 | — | ~0.34 |
| Ensemble CLIP+ResNet (w_clip=0.70) | 0.29 | 0.39 |
| OpenCLIP fine-tune | — | **0.40** |

Вывод: на шумных OSM-метках потолок ~0.40. Дальше рост дало не обучение, а **замена
источника меток** (VLM) и линейный пробинг поверх замороженного CLIP.

## CLIP linear probe по источнику меток

| Метки | Классы | Accuracy | macro-F1 | Примечание |
|-------|--------|----------|----------|------------|
| OSM (clean) | 6 | 0.265 | 0.266 | сырые OSM-метки |
| VLM content | 6 | 0.431 | 0.416 | `clip_probe_vlm6.pt` |
| **VLM oss** | **6** | **0.762** | **0.610** | продакшен, balanced-F1 0.738 |
| VLM balanced | 6 | 0.753 | 0.502 | cap active_urban@200 |

Замена OSM → VLM-меток дала прирост accuracy с 0.27 до 0.76 при той же архитектуре.
Укрупнение до 3 макро-классов ожидаемо повышает точность (0.82).

| Проверка | Результат |
|----------|-----------|
| Объектов собрано (raw) | 594 (по ~96–100 на класс) |
| Сезоны | summer 523 · autumn 384 · spring 235 · winter 152 |

## Валидация на GPKG аналитиков (другой домен)

Малые выборки (только участки с панорамой, `require_panorama=1`): analyst val n = 75,
GPKG n = 30. Цифры шумные — трактуем как индикатор, не как точную оценку.

| Чекпойнт | Analyst val acc | GPKG ML acc |
|----------|-----------------|-------------|
| clip_probe_vlm6_analyst | **0.44** | 0.33 |
| clip_probe_analyst_target_w8 | 0.41 | 0.37 |
| clip_probe_vlm6_strong | 0.27 | 0.60 |
| clip_probe_vlm3 | 0.07 | **0.67** |
| clip_probe_vlm6_oss (продакшен) | 0.25 | 0.40 |

Для сравнения — простая **текстовая эвристика по GPKG: 87.6%** (n = 7370).

### Hard-case «зелень во дворах» (natural vs urban)

| Метрика | Значение |
|---------|----------|
| Class accuracy | 0.233 |
| natural верно | 7 / 18 |
| urban верно | 0 / 12 |

### Почему ML ниже эвристики на GPKG?

1. Текст GPKG уже содержит сильные подсказки — эвристике легко.
2. 1712 участков с одинаковым текстом «зелень во дворах»: класс различается только
   панорамой, и именно здесь текст бессилен.
3. ML обучался на research-домене (VLM/OSM), а не на московском GPKG → domain shift.
4. Выборки с панорамой малы (25–75 объектов), доверительный интервал широкий.

ML ценен как дополнение к тексту на кластерах, где текст не различает класс, а не как
замена эвристики на всём GPKG.

## Воспроизведение

```bash
CUDA_VISIBLE_DEVICES=0 ./venv/bin/python scripts/training/linear_probe_clip.py \
  --metadata data/ml_perspective/metadata_perspective_vlm6_oss.json \
  --model ViT-L-14 --pretrained laion2b_s32b_b82k --select-by macro_f1
```
