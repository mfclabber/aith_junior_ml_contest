# Сбалансированный сбор датасета

## Описание

Скрипт `balanced_collector.py` автоматически собирает сбалансированный датасет панорам, гарантируя минимум N панорам, равномерно распределенных по всем классам.

## Основные возможности

- ✅ **Автоматическая балансировка**: Равномерное распределение панорам по классам
- ✅ **Итеративный досбор**: Автоматически дособирает данные для классов с недостатком
- ✅ **Учет сезонов**: Подсчитывает панорамы с учетом разных времен года (до 4 панорам на объект)
- ✅ **Безопасные перезапуски**: Можно перезапускать без дублей (благодаря стабильным OSM ID)
- ✅ **Прогресс и статистика**: Показывает детальную статистику по каждому классу

## Использование

### Базовое использование (минимум 5000 панорам)

```bash
cd /home/novichkovde/projects/classification_street_buildings/yandex-pano-downloader

python3 scripts/data_collection/balanced_collector.py \
  --target-panoramas 5000 \
  --output-dir data/balanced_dataset
```

### Большой датасет (10000+ панорам)

```bash
python3 scripts/data_collection/balanced_collector.py \
  --target-panoramas 10000 \
  --initial-max-results 2000 \
  --output-dir data/large_balanced_dataset
```

### Параметры

- `--target-panoramas` - Целевое количество панорам (по умолчанию: 5000)
- `--output-dir` - Директория для сохранения (по умолчанию: `data/balanced_dataset`)
- `--initial-max-results` - Начальный лимит OSM объектов на класс (по умолчанию: 1000)
- `--max-iterations` - Максимум итераций досбора (по умолчанию: 5)
- `--zoom` - Уровень зума панорам (по умолчанию: 1)
- `--min-per-class` - Минимум панорам на класс (по умолчанию: `target_panoramas / 6`)

## Как это работает

1. **Первый проход**: Собирает все 6 классов с начальным лимитом OSM объектов
2. **Анализ статистики**: Подсчитывает панорамы по каждому классу (с учетом сезонов)
3. **Итеративный досбор**: Для классов с недостатком панорам:
   - Увеличивает лимит OSM объектов пропорционально недостатку
   - Повторяет сбор до достижения целевого количества
4. **Финальная статистика**: Выводит сводку и сохраняет `collection_summary.json`

## Подсчет панорам

Скрипт учитывает:
- **Панорамы разных сезонов**: Если у объекта есть `panorama_spring.jpg`, `panorama_summer.jpg` и т.д., каждая считается отдельно
- **Метаданные**: Использует `metadata.json` для точного подсчета
- **Fallback**: Если метаданных нет, считает файлы `panorama*.jpg`

## Рекомендации

### Для 5000 панорам
```bash
python3 scripts/data_collection/balanced_collector.py \
  --target-panoramas 5000 \
  --initial-max-results 1000
```

### Для 10000+ панорам
```bash
python3 scripts/data_collection/balanced_collector.py \
  --target-panoramas 10000 \
  --initial-max-results 2000 \
  --max-iterations 7
```

### Время выполнения

- **1000 OSM объектов на класс**: ~2-4 часа (зависит от наличия панорам)
- **5000 панорам**: ~6-12 часов (с учетом досбора)
- **10000 панорам**: ~12-24 часа

### Перезапуск

Скрипт можно безопасно перезапускать:
- Существующие панорамы не перезаписываются
- Досбор происходит только для недостающих классов
- Статистика обновляется автоматически

## Файлы результатов

После выполнения создаются:
- `{output_dir}/collection_summary.json` - Сводка по сбору
- `{output_dir}/{class_name}/class_metadata.json` - Метаданные каждого класса
- `{output_dir}/dataset_statistics.json` - Общая статистика
- `{output_dir}/taxonomy.json` - Таксономия классов

## Troubleshooting

### Недостаточно панорам после первого прохода
- Увеличьте `--initial-max-results` (например, до 2000-3000)
- Скрипт автоматически дособерет недостающие классы

### Rate limiting
- Скрипт делает паузы между классами (5 секунд)
- При ошибках можно перезапустить - досбор продолжится

### Медленный сбор
- Это нормально для больших датасетов
- Можно запустить в `screen`/`tmux` для фонового выполнения
- Проверяйте прогресс через `collection_summary.json`
