# Описание проекта (источник для PDF)

> Конвертируется в PDF: `python submission/generate_pdfs.py`  
> Лимит для JMLC: **до 5 страниц**

Автор: **Дмитрий Новичков**, ПИК AI Lab  
Проект: классификация городских участков по уличным панорамам (6 классов UTT)

---

## 1. Задача

Аналитикам девелопера нужно оценивать состояние тысяч земельных участков: активная стройка, замороженное строительство, деградирующая застройка, недоиспользуемые площадки, природные зоны. Спутниковые снимки не показывают фасады и дворы; кадастровые описания устаревают.

**Решение:** загрузить GeoPackage с контурами участков, автоматически подтянуть уличные панорамы (Яндекс), классифицировать состояние по **6 классам UTT** и выдать результат в веб-интерфейсе с возможностью правки и экспорта в GPKG.

**Продуктовый импакт:** сокращение ручного просмотра панорам; приоритизация участков для выездной проверки; единая таксономия для аналитиков.

---

## 2. Данные

- **Контуры участков:** GeoPackage (кадастр, oid, текст `generated_land_use`).
- **Панорамы:** Яндекс Street View, equirectangular ~7168×3584.
- **Разметка для обучения:** OpenStreetMap → weak labels; переразметка VLM (Qwen/PaliGemma); правки аналитиков (7535 участков, GPKG `out_for_katya_new`).
- **Кропы:** перспектива 896×672 с точек вдоль граней полигона или из URL панорам в GPKG.
- **Объём:** ~3200 OSM-объектов, ~13k кропов; 402+ кропов с метками аналитиков.

**Ключевая находка EDA:** 29% кропов имели нулевой азимут (камера на объекте, взгляд «в никуда»); multi-heading (N/E/S/W) устранил проблему. Согласие OSM-меток с VLM — ~20%, что мотивировало чистку выборки.

---

## 3. Методы

### 3.1 Классификация (продакшен)

- **CLIP ViT-L-14** (frozen) + **линейный probe** на 6 классов.
- Обучение с перебором weight decay, class weights, label smoothing.
- Инференс: до 5 ракурсов, голосование по уверенности.
- Режим `ml` без текстовой эвристики (продакшен по умолчанию).

### 3.2 VLM (объяснимость)

- **PaliGemma 3B + LoRA:** класс + bounding box обоснования на кадре.
- Weak supervision: zero-shot + активации + правки в UI.
- Направление развития; для скорости в пилоте — CLIP probe.

### 3.3 AI-агенты

- **LangGraph metric agent:** автономно гоняет пайплайн (чистка → VLM labels → train → eval) до целевых метрик на research val.
- Использование AI-инструментов (Cursor, codegen) в разработке пайплайна.

## 4. Результаты

### Research validation (VLM-метки, n=239)

| Метрика | clip_probe_vlm6_oss |
|---------|----------------------|
| Accuracy | **76.2%** |
| macro-F1 | **61.0%** |
| balanced macro-F1 | **73.8%** |

Все 6 классов UTT покрыты. Лучшие: `active_urban` (F1 0.85), `frozen_construction` (0.80). Сложные: `underused_infrastructure`, `low_density_degraded`.

### Пилот на GPKG аналитиков

- Эвристика по тексту: **87.6%** (7370 участков).
- ML на подвыборке с панорамами: **44–80%** в зависимости от n и чекпойнта.
- Hard-case «зелень во дворах» (одинаковый текст, разные классы): ML ~23% на 30 участках — активная работа над domain adaptation.

### Инженерия

- Веб-пилот Flask + Leaflet, экспорт GPKG, статус панорамы.
- Docker, CI, воспроизводимые скрипты обучения и eval.
- Desktop-клиент (PyQt) для аналитиков.

## 5. Выводы и планы

1. **Данные важнее архитектуры:** чистка ракурсов и VLM-метки дали больший прирост, чем смена backbone.
2. **Честная валидация:** раздельные метрики research val и GPKG аналитиков; без завышения accuracy.
3. **Roadmap:** расширение analyst dataset (greenery hard-cases), fine-tune с warm-start, active learning в UI, вынос VLM в API.
